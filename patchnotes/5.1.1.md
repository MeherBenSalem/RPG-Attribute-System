# RPG Attribute System 5.1.1

## Fixes

### Ghost blocks and broken tooltips from a malformed `items_lock.json` entry

Item-lock entries were cut apart by position, so one entry missing a tag, for example
`[item]minecraft:diamond_pickaxe[itemEnd][level]12[levelEnd]` without its `[attribute]…[attributeEnd]` part, made
every block break, item use and attack throw an error. Breaks were never confirmed to the client, which left ghost
blocks, and item tooltips stopped showing requirements. Malformed entries are now skipped, and each one is named
once in the server log with the expected format:
`[item]namespace:id[itemEnd][attribute]number[attributeEnd][level]number[levelEnd]`.

### Every level-up reward is given

- All the rewards listed for a level in `levelup_rewards.json` are given. Before, only the first entry for that
  level ran, so a reward added after the default one was ignored.
- Gaining several levels at once (a large XP gain, a command, a tome) gives the rewards of every level passed, not
  only the last one. 1.20.1 already did this.

### Each attribute command uses its own `[param(x)]`

An attribute with several commands in `cmd_to_exc` applied the first command's value to all of them, so a second
command with a different `[param(x)]` got the wrong number. Each command now scales by its own `[param(x)]`; a
command without one uses the attribute's `base_value_per_point`. The value shown in the menu still follows the
first command.

No config or save changes.
