# RPG Attribute System 5.0.0 verification

This record lists what was checked for 5.0.0 "The Ascendant Update", on which source, and what was not checked. As with [4.3.0](4.3.0.md), results from one commit do not carry over to a later commit with a different tree.

## Source

The code was verified at [`02c68f7`](https://github.com/MeherBenSalem/RPG-Attribute-System/commit/02c68f79661e6c76378936ba8ce70235d1791696). The commit that adds this record changes only documentation. The tagged Publish run rebuilds, stamps and re-verifies all ten JARs at the tag commit itself.

## Local release build (2026-10-21)

All five roots were built from a clean `git worktree` checkout of `02c68f7`, not from a working copy. Each root used its required JDK (17 for 1.20.1, 21 for 1.21.1, 25 for 26.1.2, 26.2 and 26.3):

```sh
./gradlew build --no-daemon -PrasSourceCommit=02c68f79661e6c76378936ba8ce70235d1791696
```

Each root's `check` ran `mobXpTest` (112 assertions) and `rasGuiLayoutTest` (295,509 geometry, staging, preview, number and motion checks).

- **Release verifier.** `scripts/verify-release-artifacts.py --version 5.0.0 --commit 02c68f7…` passed for the complete ten-JAR set. That check covers loader descriptors, Minecraft and mod versions, source stamps, required dependencies, Java class versions, the 5.x feature classes (`SoulsLayout`, `CommitAttributeAllocationProcedure`, `StatPreviewService`), ZIP safety and hashes.
- **Publication plan.** `scripts/publish-verified-release.mjs --dry-run` produced all 20 entries: one per JAR for each of Modrinth and CurseForge. The dry run makes no uploads.
- **Fonts.** The bundled `ras_serif.ttf` and `ras_display.ttf` are byte-identical in all ten JARs. The 26.x `.gitattributes` previously normalized line endings in every unlisted file, which corrupted the fonts in git. Fonts are now listed as binary there, and this check proves the fix.

## Not verified

- **Hosted native QA.** At the time of this record, the native-client protocol (Fabric 1.21.1 and 26.3 at GUI scales 2, 3 and 4) had not run on this source.
- **Row clicks.** Selecting a row by clicking it, and right-clicking a row to remove a point, were fixed in `919d0b8`, after the client smoke tests. That fix is covered by code review and the builds above. The chevrons, keyboard and tooltips were tested in clients before the fix and are unchanged by it.
- **Multiplayer.** No test had two players on one server, and no client joined a dedicated server.
- **Legacy screens on 26.x.** The restyled `PlayerAttributesViewerGUIScreen` and `PlayerStatsOverviewScreen` open only from another mod or a command that sends the older button action. They compile in every root, but were reviewed by screenshot only on 1.21.1.
- **Background blur on 1.20.1.** 1.20.1 has no menu blur, so `background_blur` has no effect there. That is expected, not a defect.
- **Coverage gaps carried over from 4.3.0.** The limits listed in the [4.3.0 record](4.3.0.md#native-gameplay-and-visual-limits) still apply, including physical combat and datapack reload.

## Publication

Pushing tag `v5.0.0` starts the Publish workflow. It rebuilds all ten JARs at the tag, verifies them again, and uploads with the existing repository secrets. Upload receipts are kept in that run's `release-provenance-<commit>` artifact. A file counts as public only when Modrinth lists it as a `release`, or when CurseForge shows it as available and approved. A file still in CurseForge review is not yet public. Store descriptions are not updated by the workflow; the listing text is in [`marketing/curseforge/description.md`](../../marketing/curseforge/description.md).
