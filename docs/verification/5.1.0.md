# RPG Attribute System 5.1.0 verification

This record lists what was checked for 5.1.0 and what was not. As with [5.0.1](5.0.1.md), results from one commit do not carry over to a later commit with a different tree; the tagged Publish run rebuilds and re-verifies all ten JARs.

## Source

The code, docs and tooling changes are in `aa339b4` on branch `ccr-17faeee5-ros3lp` (PR #58). The commit that adds this record changes no code.

## Report

"The text position when you level up feels slightly offset."

## Cause, measured in real clients

A temporary capture harness (not committed) drew each bundled text face at a known y on a black screen, triggered real level-ups with `/ras add level`, and captured the frames from Xvfb. Frames were measured per pixel. Values are in GUI pixels relative to the draw y; capitals were measured on the letter H.

| Face | Capitals, 1.21.1 (FreeType) | 1.20.1 (stb_truetype) | 26.3 (Vulkan) | What 5.0 assumed |
| --- | --- | --- | --- | --- |
| Body (EB Garamond) | 0.5 to 7.5 | 0.5 to 7.5 | 0.5 to 7.5 | 0 to 9 |
| Section (Cinzel 9.5) | 1.0 to 7.5 | 1.0 to 7.5 | 0.5 to 7.5 | 0 to 8 |
| Page title (Cinzel 15) | −3.5 to 7.0 | −3.0 to 7.0 | −4.0 to 7.0 | 0 to 11 |
| Banner title (Cinzel 30) | −14.0 to 7.0 | −14.0 to 7.0 | −14.5 to 7.0 | 0 to 22 |

Results were the same at GUI scales 2, 3 and 4 (within one physical pixel). Minecraft puts the baseline of every bundled TrueType face about 7 pixels below the draw y whatever its size, so large faces rise above it. 5.0 centered text as if it filled a box below the draw y:

- **Banner (the report).** In the 5.0.1 source, at GUI scales 2 and 3, the title's capitals started 3 pixels *above* the upper gold rule and covered the diamond ornament, leaving 30 pixels of empty space below them: the capitals were 15 pixels above the midpoint of the two rules. With `"font": "minecraft"` the title was about 5 pixels high.
- **Menus.** The page title in the header sat about 4 pixels above the book icon and the tabs. Body text in rows and buttons sat 0.5 to 1 pixel high.

## Fix

`RasTheme.Face` carries the measured ink box, and text is centered by it (`Face.centerY`). The banner geometry is a plain-Java `BannerLayout` with regression checks (equal 12-pixel space above and below the title for both fonts, over screen heights 120 to 1080 and every position setting).

| Banner measurement (5.0.1 source → 5.1.0) | 1.21.1 | 1.20.1 | 26.3 |
| --- | --- | --- | --- |
| Title capitals minus midpoint of the rules, scale 2 | −15 → 0 | – → 0 | – → −0.25 |
| Same, scale 3 | −15 → 0 | – → 0 | – → 0 |
| Space above / below the title, scale 3 | 0 / 30 → 12 / 12 | – → 12 / 12 | – → 12 / 12 |
| Same with the vanilla font, scale 3 | → 12 / 12 | → 12 / 12 | → 12 / 12 |

The 5.0.1 column was captured from an untouched checkout of the parent commit on 1.21.1 Fabric; the faces' metrics show the same cause on every root.

## Customization checked in real clients

On Fabric 1.21.1 (OpenGL llvmpipe), Fabric 1.20.1 (OpenGL llvmpipe) and Fabric 26.3 (Vulkan lavapipe), the harness rewrote `ui.json` and `texts.json` while the game ran and captured the result without restarting:

- custom accent, text and increase colors in the menu, HUD and banner
- banner at `level_up_banner_position` 0.2, background opacity 0.45, duration 6, detail line removed and restored
- `texts.json`: `§`-colored banner title with a placeholder, an emptied hint, a reworded points line, French tab, section, button and hint texts; an emptied footer prompt was dropped
- HUD width 220 without experience numbers; HUD without level line or background; `hud_idle_opacity` 0 hid the HUD after one idle second and a level-up brought it back
- banner disabled; classic HUD with the configured experience text
- menu background opacity 0.55 and tooltip delay 0

A shorter run (banner, Level Up page, then custom colors, banner position and texts applied live) passed on the other loaders:

## Builds and checks

### Dedicated servers

Each of the ten loaders booted a real dedicated server (`runServer`) on a flat world, reached `Done`, logged `[RPGAS] Loaded`, generated `display/ui.json` (all 28 keys) and `display/texts.json`, and stopped cleanly with no errors. NeoForge and Forge run tasks do not forward console input, so those servers were stopped through Minecraft's shutdown hook (SIGTERM), which logged `Stopping server` and saved the worlds. Forge 47.2.30's own `advertiseDedicatedServerToLan` default loads a client class on this Linux host (`LanServerPinger`, no RAS frames in the stack); it was turned off in that run's `forge-server.toml`.
