# 4.3.0 development verification

This is a development branch. No release tag, store publication, or merge is part of this work.

## Focused checks

The rules/cache tests compile the **actual isolated production copies** with Java `--release 17` and a cached Gson jar. They cover disabled defaults, unknown-field preservation, rule precedence/ties, explicit zero, weighting gates, fractional effective armor, overflow/nonfinite values, dynamic tag predicates, unsupported schema, unreadable/malformed reloads, cached evaluation, and the actual config-studio ZIP→JSON export fixture.

```sh
python3 scripts/test-mob-xp.py --gson-jar /path/to/gson.jar
```

The gameplay regression harness compiles the **actual** `ConfigInitializer`, `ConfigValidator`, `MobXpConfig`, `GameplayRulesProcedure`, and `LevelingService` source with minimal Minecraft/platform test doubles. It verifies imported file preservation, corrected fresh-only stats labels, startup validation modes, dimension replacement, multiplayer shared-pool conservation/radius/dimension exclusion, vanilla/client/summon bypass, effective fractional armor, legacy player migration, reset progression, repeated sync, and rejected invalid/overflowing amounts.

```sh
python3 scripts/test-gameplay-regressions.py --gson-jar /path/to/gson.jar
```

These checks are distinct from loader/API builds and in-game integration. They do not prove loader death-event cancellation/deduplication, network packets, real datapack reload, real combat, or client rendering.

Each common Gradle `check` also runs the plain-Java `mobXpTest` and `rasGuiLayoutTest` regression entry points. Build each isolated root with its required Java toolchain:

```sh
cd 1.21.1 && ./gradlew build --no-daemon
```
